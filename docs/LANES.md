## One rung, start to finish

1. **Merge main first.** `git fetch origin && git merge origin/main`. The generated state files conflict by design when main and a worktree both ran the pipeline. Resolve by union, never by side. For each conflicted file, write the two sides out and union them:

       git show :2:data/events.json > ours.json && git show :3:data/events.json > theirs.json
       node tools/merge-state.cjs events ours.json theirs.json data/events.json

   Kinds: `events` (by id, later `last_seen` wins), `watchlist` (by platform|handle, later `last_checked` wins), `review` (by brand|start|venue, ours wins), `geocache` (by key), `budget` (max `used_month`). `data/hashtags.json`: take main's and union `ids` and `missing`. `site/data/*.json`: take main's (`git checkout --theirs`) and regenerate. `LADDER.md`: keep both sides. Then `git add` the files, commit the merge, `npm test`.
2. **Before snapshot.** `node tools/percity.cjs data/events.json > before.json` (upcoming = end date, or start, on or after today; per city and total). `npm run audit -- --counts` for the quality counts (no matcha signal, off-topic, duplicate-looking pairs, "the writer would drop").
3. **The work.** Population: pick the top two sources by expected dated-event yield (see "Population" below), build or extend the adapter in `ingest/lib/sites/`, register it in `ingest/lib/sites/index.js` (`NAMES`, `SITE_ORDER`, cap), add a test with a saved fixture page, run `npm run discover -- --only <site> --cities <names> --no-social-search` over the 30 biggest metros (below), wait 10 minutes on a 429 and continue with the cities not reached. Events: see "Events" below. Either way the verification rule is the same: open the page for anything unsure before promoting it.
4. **Promote and regenerate.** `npm run ingest` (review promote step, geocode, art, pages, feeds, event pages, weekend, brand extras, sitemap; 60 to 90 minutes, run it in the background with a log). The Instagram Graph adapter inside it shares the hourly Meta allowance with main's scheduled run and stops cleanly on code 4. Never run two pipeline writers at once in one worktree (`watch`, `discover` and `ingest` all write `data/review/<date>.json`; `watch` and `ingest` write `data/events.json`).
5. **Check.** `npm run audit -- --counts` ("the writer would drop 0" must hold; pottery, pilates, run clubs, networking meetups and classes without walk-in matcha are not pop-ups), `npm test` (all green), `npm run smoke` (every check at 1440 and 390; set `CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe"` if Chrome is not found).
6. **Ship.** Merge `origin/main` again (step 1 rules), `git push origin HEAD:<your branch>`, confirm `git merge-base --is-ancestor origin/main HEAD`, `git push origin HEAD:main` (fast-forward only; never force), then `npm run deploy` (stamps the shell version, deploys with wrangler), then `npm run smoke -- --url https://matchamap-cu7.pages.dev` and `curl -s https://matchamap-cu7.pages.dev/sw.js | grep VERSION`.
7. **After snapshot and board.** `node tools/percity.cjs data/events.json > after.json` then `node tools/percity-table.cjs before.json after.json` prints the per-city table and the distinct-cities-per-state table. Update your lane's row in the Lanes table at the top of `LADDER.md` (state, last rung, next rung) and add a dated line under your lane's log heading. Population also updates `docs/DISCOVERY-YIELD.md` (fetched, candidates, dated, promoted, dropped by reason per source) and `docs/SOURCES.md`.
8. **Report** to the command center in one message: first line the headline (what shipped or what is blocked); then the numbers (events, upcoming, distinct cities per state for the thin metros Denver, Las Vegas, Phoenix, Charlotte, Nashville, Columbus, Indianapolis, Jacksonville, Fort Worth, Oklahoma City, before and after; yield per source or counts per rung; tests; smoke); the commit on main and the live worker version; usage. Then start the next rung without waiting.

## Review-queue conventions

- `data/review/<date>.json` is the crawlers' run file (rewritten by `discover`, `watch` and `ingest`; items merged by key). Sweep and lane files are `data/review/<lane-or-group>-<name>.json` with shape `{generated, group, items}` and are never rewritten by the pipeline. Item fields: brand, handle, source_id, title, start, end, all_day, tz, venue, address, city, state, zip, lat, lng, source_url, posts, evidence, menu, price, hours, pay, description, image_url, confidence, notes.
- `npm run ingest` promotes an item when `confidence` is `confirmed` or `likely` AND the notes carry none of the hedge words (`placeholder|inferred|assum|sample date|not checked|holiday risk`); use those words on purpose when they are true. Confirmed = date + time + street address on a public page; likely = date plus time or venue. A weekly schedule counts: brand page gives day + venue, market page gives hours and address, one item per date up to 8, notes "weekly schedule from <url>; hours from <url>".
- Notes starting `dropped: <reason>; ` hold an item back and tell the human why; "checked <date>: <what the page shows>" marks an unsure item as opened. Do not reopen items already marked checked today. Keep the queue under 20 by settling items, never by deleting them without a reason in notes.
- Drop by event id, pin by id or address, and rename a city by id all go in `data/overrides.json` (`{"<id>": {"drop": true, "why": ...}}`, `{"lat":..,"lng":..}`, `{"city": "Washington", "state": "DC", "why": ...}`); the writer applies city overrides to stored events and snaps approximate pins to the city file's centre on every write. A city whose Census point is in water gets a row in `LAND_POINTS` in `tools/gen-cities.js` (San Francisco, Corpus Christi so far), then `node tools/gen-cities.js --site-only --no-fetch`.
- City names: lower-case listing cities are title-cased by the writer; a region ("Northern Virginia") is not a city: fix the source's `home_city` and override the stored events.
